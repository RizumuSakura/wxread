# 进度保护：验证范围与安全边界

## 本轮实现

- 浏览器 `appId` 来自 User-Agent，不是运行唯一标识。旧记录不能把同浏览器标识之后的所有写入都当成本次提交。
- 对没有恢复候选快照的旧任务，自动恢复只接受同标识、有效数值时间，且更新时间位于最后写入时间的 **前 2 秒至后 60 秒**，同时不超过当前时间后 5 秒。这个窗口是保守的归属筛选，不是服务端保证。
- 来源不明、时间窗口之外的变化不自动回滚，也不删除原始恢复记录；任务停止，不进入下一本、不推进书架游标。
- 本次写入造成位置变化时，下一次写前检查会停止新提交，让结束保护尝试恢复，而不是误当成手机修改并丢弃原始记录。
- 恢复前持久化并上传完整的 `restore_from` 候选快照、原始位置及恢复写入时间；上传成功后再次回读。上传失败或当前位置变化，不执行恢复写入。
- 恢复失败后的跨运行重试，只恢复与 `restore_from` 完全一致的状态；如果已回到原始章节、位置、百分比，则直接核对并清理记录。新时间戳不会扩大已批准候选的归属范围。
- `last_write` 不接受布尔值、负数、NaN、无穷大或字符串；恢复候选也必须包含完整有效的位置字段。

## 自动化验证（离线，不访问真实账号）

在仓库根目录、使用已安装开发依赖的 Python 执行：

```text
python -m unittest discover -s tests -v
```

`tests/test_recovery_integration.py` 使用合成凭据与响应，替换整个 HTTP 传输层，并阻止非夹具请求；真实执行加密文件读写、请求签名、进度核对与主程序停止分支。检查点上传被替换为加密文件复制，不调用 GitHub Cache。

覆盖：

1. 已改变的位置通过签名恢复请求写回，并从模拟服务回读；恢复不附带阅读时长。
2. 子进程在写入后用 `os._exit(23)` 异常退出、不运行清理；新会话从加密检查点副本恢复。
3. 模拟网络中断时保留加密记录；网络恢复后重试。
4. 模拟手机修改时保留新进度并停止，不进入书架任务、不改变游标。
5. 相同浏览器标识在旧时间窗口之后的修改不被回滚，恢复记录保留。
6. 接口成功但回读未恢复时，不宣称成功、不开始下一本。
7. 恢复检查点期间发生手机修改，不执行恢复写入。
8. 失败恢复的候选快照可经加密检查点跨会话重试。
9. 恢复期间同浏览器发生并发修改，即使下一次从云端检查点重试，也不能被新的恢复时间戳误认领。

上述是**离线集成验证**，不是微信读书服务端验证、真实手机并发或真实 GitHub 工作流强制终止验证。短测也不证明长期稳定或时长到账。

## 仍待受控真实验证

需先明确测试书籍、账号及可接受的进度变更范围，再单独执行；不因单元/集成测试通过自动触发。

| 场景 | 必须记录的证据 | 通过条件 |
| --- | --- | --- |
| 已变化位置的真实恢复 | 起始章节/位置/小数百分比、变化后值、恢复请求与回读结果（脱敏） | 回到原始位置；恢复不累计时长；未提前换书 |
| 手机并发 | 修改前后位置及顺序、脚本停止结果、书架游标 | 保留手机新位置，不继续下一本 |
| 强制终止/断网后跨工作流恢复 | 检查点来源运行、待恢复记录、下次回读及写入结果 | 先处理旧记录；失败时无新阅读提交 |
| 长时间运行 | 各书核对结果、异常和重试、客户端实际计入记录 | 不把等待秒数当作服务端计入证明 |

## 来源不明时如何处理

1. 先停止同账号的其他脚本运行；不要在还有恢复记录时删除云端缓存、换扫码账号或回退保护代码。
2. 查看对应书籍的起始日志，核对原始章节、章节位置和小数百分比；私密书名可能已隐藏。
3. 通过客户端人工判断应保留哪个位置。不要通过编辑加密记录或扩大时间窗口强行“通过”保护。
4. 若决定恢复原始位置，先在客户端完成精确核对/调整，再运行一次 `check_auth`：它会先处理旧记录；原始章节、位置、百分比一致时才清理记录。若客户端不能精确调整或无法确认原始位置，保留加密记录并停止，进一步人工处理。
5. 若决定保留新位置但脚本因来源不明而停止，不要直接删除恢复记录绕过保护；当前没有自动授权覆盖或丢弃原始记录的入口。

## 已知限制

- 没有服务端条件更新/版本校验，最后一次回读与写入间仍有竞争窗口。同标识、短窗口内的真实并发不能完全区分。
- 极端网络延迟、时钟偏差、服务端归一化，或长任务中恢复了较旧云端检查点，可能触发保守停止，需要人工核对。
- 强制终止不能保证当场恢复；云端检查点可用性和最终状态保存仍依赖 GitHub 与网络。
- 离线测试通过不代表已部署，线上行为以实际运行的提交版本为准。
